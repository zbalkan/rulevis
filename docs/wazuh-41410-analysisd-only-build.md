# Narrow Wazuh 4.14.10 debug build for RuleVis

The workflow `.github/workflows/native-wazuh-41410.yml` builds the
`wazuh-analysisd` ELF target at pinned Wazuh tag `v4.14.10`.
It never invokes the `server`, `build`, or `agent` aggregate targets,
never builds other manager/agent executables, and never installs a Wazuh
manager onto the runner.

## Verified upstream dependency boundary

The `TARGET=server` make variable selects the correct Wazuh manager
compilation definitions; the explicit `wazuh-analysisd` make goal
selects the one requested executable.

**Some non-analysisd object files remain mandatory.** Wazuh's upstream
`libwazuh.a` collects every `config/*.o`, `wmodules_dep`,
shared code, and database helper objects. The `config/config.c` parser
references module configuration functions and their `WM_*_CONTEXT`
definitions. Attempts to override `wmodules_dep=` produced 127
undefined references. Retaining the database helpers and enabling
`-ffunction-sections/-fdata-sections` with `--gc-sections` resolved
the database symbols but did **not** eliminate references to module
contexts from the configuration parser.

We therefore keep the **unmodified upstream `libwazuh.a` prerequisites**
until a *verified and source-faithful* analysisd-specific separation is
implemented. This compiles some shared module objects which analysisd
needs to link, but no unrelated agent/manager executable.

The previous missing generated-header error originated in
`wm_syscollector.c`, whose required `rsync_schema.h` and
`syscollector_deltas_schema.h` headers are generated by upstream
FlatBuffers CMake rules. The workflow builds the bundled FlatBuffers
dependency and invokes only its `compile_schemas_input` target,
rather than the whole Wazuh CMake build group.

The upstream `deps` target downloads a broad collection of source
dependencies. Future optimization can target these downloads once
the source-faithful debug binary and native GDB capture are working.

## Scope checks and evidence

The validator requires exactly one Wazuh service executable in the
upstream src root, `wazuh-analysisd`. It validates ELF identity,
DWARF `.debug_info`, GDB visibility of `_setlevels`, `RuleNode`,
`RuleInfo`, and `Config`, and runtime library resolution.
Compiled object files or third-party build utilities are not
mistaken for additional service executables.

Only the selected binary, necessary local shared libraries, build and
linkage logs, source provenance, and debug-symbol evidence are uploaded
as `wazuh-41410-analysisd-debug` (14-day retention).

This does not constitute a native differential test. Separate isolated
runtime provisioning and GDB fixture execution are still required.


## GitHub Actions dependency cache

The workflow caches Wazuh's extracted and compiled third-party dependency
trees under `src/external`, `src/external-precompiled`, and the
`shared_modules/http-request` dependency. A full cache hit skips
`make deps`; the subsequent FlatBuffers and analysisd Make targets
still execute normally and can reuse existing library build outputs.

The cache key includes the pinned Wazuh source commit, upstream Makefile
hash, runner OS and architecture, runner image version, and debug build
configuration. There are deliberately **no broad restore keys**: mixing
different Wazuh versions or runner toolchains risks incorrect or
irreproducible native results. A cache is saved only after a successful
workflow run. Cache eviction remains under GitHub's retention and
quota policies.

This cache accelerates repeated runs without treating a restored binary
as validation evidence. Every run still rebuilds/checks the selected
`wazuh-analysisd` executable, checks GDB symbols, and uploads an
independent provenance manifest. The official APT packages and source
checkout are not cached.

## Commands

The native compile step retains the upstream prerequisite graph:

`make -C native-wazuh/src TARGET=server DEBUG=yes DISABLE_JEMALLOC=yes -j2 wazuh-analysisd`

Never replace this with `make TARGET=server build` or `make TARGET=server server`.
